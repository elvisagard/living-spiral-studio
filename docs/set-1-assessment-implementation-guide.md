# Set 1 Visual Replication Assessments: Implementation Guide

## Purpose

This document is the working guide for producing, publishing, and delivering the four Set 1 Visual Replication assessments that follow Challenge 1.

The governing assessment question is:

> Can the student independently reproduce a provided visual using the Google Slides production skills learned in Project 1?

Set 1 assesses visual replication and Google Slides control. It does not assess original design. Students receive a target, exact copy, and raw assets, but no click-path tutorial or preassembled components.

## Non-Negotiable Rules

- Every visible feature must be reproducible with ordinary Google Slides tools taught in Project 1.
- Students reproduce the supplied target; they do not add, remove, or redesign content.
- Student-facing pages provide exact copy and raw assets but no click-path tutorial.
- Student-facing pages provide exact slide dimensions in inches.
- Student-facing pages identify the exact font families and required weights, but do not provide font sizes.
- Students sample colors from the target visual; student pages do not provide palette hex values.
- Raw photos and icons must not be premasked, precropped, precolored, or assembled into finished components.
- Images and icons must preserve their proportions.
- No database or R2 storage is required. Assessment pages and assets remain lightweight and local to the application, outside the public static directory.
- Target images open in an accessible lightbox and are downloadable.
- Minor manual placement differences are acceptable; pixel-perfect reproduction is not required.
- The student target image is the visual authority for the construction.
- Each assessment uses the exact four-criterion, 12-point rubric from its approved dossier.
- Google Classroom items remain drafts until the final review gate unless explicit approval is given to publish.

## Phase 0: Resolve and Lock the Specification

**Goal:** Establish one unambiguous specification for each assessment.

### Work

- Record the approved overview image as the visual authority and document any deliberate contrast correction.
- Reconcile any remaining differences in copy, palette, typography, dimensions, assets, and required operations.
- Confirm the final titles and web slugs.
- Confirm the names of the three Technology classes and the Classroom topic under which the assessments will appear.
- Record whether Classroom assignments should be created as drafts, scheduled, or published.

### Deliverables

- Four locked assessment specifications.
- Final slug map.
- Final asset list for each assessment.
- Classroom delivery settings recorded in this guide.

### Exit gate

The user approves the four specifications. No production ambiguity remains.

## Phase 1: Asset Inventory and Preparation

**Goal:** Prepare only the raw materials students are allowed to receive.

### Work

- Inventory each required photograph, icon, and other raw source asset.
- Obtain or create missing raw assets that match the approved target.
- Remove accidental preassembly, masking, cropping, formatting, or embedded labels.
- Export optimized web previews while preserving full-resolution downloadable originals.
- Use predictable filenames and assessment-specific folders.
- Record image dimensions, file type, and intended student use.

### Deliverables

- Raw student asset folders for 1A, 1B, 1C, and 1D.
- Optimized target previews.
- Full-quality downloadable targets and raw assets.
- Asset manifest with source and usage notes.

### Verification

- No student asset reveals a completed assessed operation.
- No image or icon is distorted.
- Web previews are visibly faithful and appropriately compressed.
- Every downloadable file opens correctly.

## Phase 2: Prepare the Student Target Visuals

**Goal:** Give students a clear visual target that can be reproduced with ordinary Google Slides operations.

### Work

- Set the required canvas dimensions.
- Construct each approved target from text, shapes, images, icons, and layers available in Google Slides.
- Preserve exact copy, fonts, colors, counts, spacing relationships, and hierarchy.
- Keep independently manipulated objects within the dossier's intended complexity.
- Run an adult completion-time pilot.
- Simplify only when the pilot exceeds the expected range, without removing the focal skill.

### Deliverables

- One clean exported target image for each assessment.
- A short construction record naming the objects and operations used.

### Verification

- Target export and student directions match.
- Nothing requires external image editing, custom vector drawing, gradients, or obscure workarounds.
- Adult completion times fall within the approved pilot ranges.
- Every required visual operation can be completed by students in Google Slides.

## Phase 3: Lock the Student Slide Setup

**Goal:** Make slide creation and exact custom dimensions part of the assessed work.

### Work

- Display the exact dimensions in inches on every assessment page.
- Tell students to create a new Google Slides file and apply those dimensions.
- Supply raw assets individually from the assessment page.
- Treat correct canvas dimensions as part of Formatting Control.

### Deliverables

- Four student-facing dimension specifications.
- Four assessment pages containing the target, copy, fonts, and raw assets.

### Verification

- No starter slide is supplied.
- Every page states the exact width, height, and orientation.
- Classroom instructions require students to create the file and set its dimensions.
- Assets remain raw and reusable.

## Phase 4: Build the Assessment Web Pages

**Goal:** Extend the lightweight Challenge 1 experience into a consistent assessment set.

### Shared page content

- Assessment name and product type.
- One-sentence task.
- 20-minute limit.
- Large target preview with accessible lightbox.
- Target download.
- Exact copy in a readable, copyable format.
- Raw asset downloads.
- Clear instruction to create a new Slides file and set its custom dimensions.
- Submission reminder.
- No tutorial, hints, solution steps, teacher key, or rubric scoring guidance intended only for teachers.

### Implementation expectations

- Reuse the established `/challenge-1` visual language where it supports consistency.
- Keep pages static, responsive, keyboard accessible, and fast-loading.
- Prefer optimized WebP previews and retain appropriate originals for download.
- Avoid unnecessary dependencies, client-side state, animation, and decorative complexity.
- Give each page unique metadata and meaningful alternative text.

### Deliverables

- Four assessment routes.
- Shared assessment components where reuse reduces duplication.
- Local static asset directories.

### Verification

- Production build passes.
- Every route loads directly and on refresh.
- Lightboxes open and close by pointer, close control, overlay, and Escape key.
- Copy and download controls work.
- Mobile and desktop layouts remain readable without overlap.
- Page weight and image loading remain appropriate for classroom use.

## Phase 5: Prepare Teacher Materials

**Goal:** Give teachers everything needed to administer and score each assessment consistently.

### Work

- Copy each approved dossier rubric exactly into a Classroom-ready format.
- Create a brief teacher key naming assessed operations and common errors.
- Include the dossier's rapid-check order and fidelity tolerances.
- Keep teacher materials separate from student-facing downloads.
- Cross-check the target, student page, rubric, and key for consistency.

### Deliverables

- Four exact 12-point rubrics.
- Four brief teacher keys.
- Student assessment-page links.

### Verification

- Each rubric has four criteria totaling 12 points.
- Criterion values remain `2 / 1 / 0`, `3 / 1.5 / 0`, `3 / 1.5 / 0`, and `4 / 2 / 0`.
- No wording has drifted from the approved dossier.
- Teacher keys do not introduce requirements absent from the student target or rubric.

## Phase 6: End-to-End Quality Assurance

**Goal:** Validate the complete student and teacher experience before Classroom creation.

### Work

- Complete each assessment from a new Google Slides file as a student would.
- Time the workflow and note any friction or unintended demands.
- Compare the completed work with the target image.
- Score a sample using the rubric to test whether each criterion is observable.
- Test downloads, permissions, links, keyboard access, responsive layouts, and production builds.
- Correct contradictions or broken materials at their source.

### Exit gate

The user reviews and approves the complete package for all four assessments before Classroom items are created.

## Phase 7: Create Google Classroom Classwork

**Goal:** Reproduce the approved assessment package consistently in all three Technology classes.

### Work

- Use the signed-in in-app browser to identify the three intended Technology classes.
- Create or select the agreed Classroom topic.
- Create one Classwork assignment per assessment in each class.
- Use consistent titles, directions, point values, attachments, and settings.
- Link the student assessment page as the single source for instructions and assets.
- Do not attach or provide a starter slide.
- Build the exact 12-point rubric for the corresponding assessment.
- Confirm due dates, scheduling, and visibility settings.
- Keep assignments as drafts unless publication has been explicitly approved.

### Verification

- Twelve total assignment instances exist: four assessments across three classes.
- Every assignment points to the correct assessment page.
- Every rubric matches the corresponding approved dossier and totals 12 points.
- Instructions require students to create their own Slides file and set its dimensions.
- No teacher key or answer reference is visible to students.
- Titles, instructions, attachments, and settings are consistent across classes.

### Exit gate

The user reviews the drafted Classwork items and authorizes scheduling or publication.

## Phase 8: Publish and Record Completion

**Goal:** Release the assessment set cleanly and preserve a reliable implementation record.

### Work

- Publish or schedule the approved Classroom assignments.
- Recheck student-visible assignment views in each class.
- Record final URLs, Classroom destinations, release settings, and repository commit.
- Document any intentional class-specific differences.
- Preserve the final asset manifest and QA results.

### Deliverables

- Published or scheduled assessment set in all three classes.
- Final delivery record.
- Repository changes committed and pushed to the approved branch.
